# Security policy

HealthLake is a technical demonstration using synthetic data only. It is not a certified healthcare platform and
is not intended or authorized to process real personal health data. **Never load real patient data.**

## Reporting
Report vulnerabilities privately to the repository owner (GitHub private vulnerability reporting). Do not open a
public issue with exploit details.

## Security design (summary)
- Secrets live in `.secrets/` (git-ignored), are generated by `scripts/bootstrap.py`, mounted as Docker secrets at
  `/run/secrets/*` and read through `*_FILE` variables. `.env.example` contains no secret. No default password.
- PostgreSQL is not exposed; Airflow, API and dashboard listen on 127.0.0.1 only. No Docker socket is mounted.
- Separate database roles (ADR 0002): ingestion, dbt, publication, API read, owner/migrations, Airflow metadata.
- API: hashed keys compared in constant time, scopes `read`/`ops`, parameterised SQL, read-only sessions with a
  statement timeout, no free SQL, no names or addresses, schema names never taken from user input.
- Containers run as non-root (API/dashboard UID 10001, read-only root filesystem, all capabilities dropped;
  Airflow images as UID 50000), `no-new-privileges`.
- Logs: secrets are redacted; resource bodies are never logged.
- Backups contain no secret (roles dumped without passwords); keep `.secrets/` separately.
- CI: actions pinned by commit, `contents: read`, gitleaks, pip-audit on every lockfile, Trivy scan of the API image.

## Known limits
- Bronze immutability is application-level (exclusive create, verification), not WORM storage.
- Local demo TLS is not configured (loopback only). Do not expose the ports on a network.
